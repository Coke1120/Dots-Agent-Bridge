# Dots Agent Bridge v0.2.0

This release adds **OpenBot and generic MCP-agent client support** to the existing private Hermes ↔ ChatGPT Dots mailbox. It is an additive compatibility release, not a replacement of the verified Hermes path.

## Highlights

- Introduces a dedicated `agent` OAuth role with least-privilege `bridge:submit` and `bridge:read` scopes. Dot-only response and subscription capabilities remain inaccessible to agent clients.
- Allows one approved Dot plus one or more authorized Hermes or MCP agent submitters to use the same owner-scoped mailbox.
- Adds `hermes-dots-bridge init --submitter agent` for fresh OpenBot-only installations, plus an OpenBot/Dot policy template.
- Makes the `talk-to-dot` skill reusable from OpenBot as well as Hermes.
- Adds an OpenBot setup guide with native MCP OAuth, host/Docker networking, audience, security and acceptance-test instructions.
- Expands synthetic JWT, scope-isolation and MCP round-trip coverage across Python 3.12/3.14 and pinned MCP SDK 1.x/2.x.
- Documents a separate design for future Dot-initiated OpenBot task dispatch; **direct dispatch is not part of v0.2.0**.

## Compatibility and rollout

The repository, Python distribution, command `hermes-dots-bridge`, MCP identity, OAuth audiences, SQLite schema, `request.created` webhook contract and existing Hermes workflow remain unchanged. Do not replace a live bridge database, encryption key, OAuth client or subscription while upgrading.

To authorize OpenBot against a running bridge, add a separately verified OAuth client as role `agent` in the protected operator policy. Follow [docs/openbot.md](https://github.com/Coke1120/hermes-dots-bridge/blob/main/docs/openbot.md) for the exact procedure. Do not reuse a Hermes or ChatGPT credential. Same-owner submitter clients can see the same retained mailbox content; grant access only to trusted clients.

**Validation boundary:** CI verifies the offline MCP/JWT workflows, not a real OpenBot ↔ Dots production connection. Verify a live synthetic round trip and expiry/renewal/reboot handling before claiming unattended reliability. GitHub release publication does not deploy or reconfigure the Mac mini.

A future, separately reviewed change may rename the repository to `dots-agent-bridge`; no rename is included in this release.
